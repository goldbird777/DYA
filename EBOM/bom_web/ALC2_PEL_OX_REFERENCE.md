# DYA ALC-2 웹 구현 참고: PEL 코드로 MES O/X를 만드는 원리

> 목적: Windows용 `DYA_ALC2_LOCAL` 프로그램과 실제 Excel 마스터의 업무 원리를 웹 구현자가 이해하기 위한 참고 문서다.  
> 이 문서는 기존 코드를 그대로 복사하라는 요구사항이 아니다. **최종 판정 기준은 HKMC ALC 원본의 PEL 코드, PEL CODE 마스터, MES/★통합 ALC2 템플릿의 열별 규칙이다.**

## 1. 한 문장으로 설명

Q파트의 KEY02~KEY06으로 좌석별 ALC 코드집의 행을 찾고, 그 행에 들어 있는 6자리 PEL 코드들을 PEL CODE 마스터의 사양명으로 번역한 다음, ★통합 ALC2 코드 서식의 해당 좌석·해당 사양 열에 `O`, 미적용 열에 `X`를 기록한다.

```text
Q파트 KEY02~KEY06
  → 좌석별 ALC CODE(B열) 행 검색
  → 그 행의 PEL/COMBI 코드 수집
  → PEL CODE 마스터에서 사양/설명 조회
  → ★통합 ALC2 고정 열과 정확히 연결
  → 적용=O, 미적용=X
```

ALC 4자리 문자열을 분해해 O/X를 만드는 것이 아니다. **그 ALC 코드에 해당하는 원본 행에 어떤 PEL 코드가 들어 있는지**가 기준이다.

## 2. 입력 6파일과 좌석 연결

| Q파트 | 업로드 슬롯 | 의미 | ★통합 ALC2 상단 그룹 |
|---|---|---|---|
| KEY02 | FRT LH | 전석 LH | LHD면 DRIVER, RHD면 PASSENGER |
| KEY03 | FRT RH | 전석 RH | LHD면 PASSENGER, RHD면 DRIVER |
| KEY04 | RR BACK LH | 2열 등받이 LH | Rr 2ND LH |
| KEY05 | RR CUSH | 2열 쿠션/센터 | Rr 2ND CTR or CUSH |
| KEY06 | RR BACK RH | 2열 등받이 RH | Rr 2ND RH |

기본 조합:

```text
KMC ALC-2 CODE = KEY02 + KEY03 + KEY04 + KEY05 + KEY06
```

- 각 KEY는 보통 4자리다.
- Q파트의 `X`는 미사용 좌석이며 조합 코드에서는 `****`로 바꾼다.
- 차종에 따라 KEY 그룹 수가 늘어날 수 있으므로 20자리만 고정 가정하면 안 된다.
- 전석의 DRIVER/PASSENGER는 LH/RH만으로 고정하면 안 되고 LHD/RHD를 먼저 판정해야 한다.

## 3. ALC 코드집에서 읽어야 하는 정보

실제 HKMC ALC 코드집의 대표 구조:

- B열: `CODE` — Q파트 KEY와 매칭할 4자리 코드
- C열: `PART NO`
- G열: `PART-NAME`
- M:S 부근: 지역/사양군
- T/U 부근: LHD/RHD
- V열 이후: COMBI/OPTION 영역
- COMBI/OPTION 셀: `5693A3`, `8811F2`, `8821A5` 같은 6자리 PEL 코드

웹 파서는 CODE 집합만 읽으면 안 된다. 다음 형태로 **CODE별 전체 PEL 코드 집합**을 만들어야 한다.

```json
{
  "500A": {
    "part_no": "88005 P1000N21",
    "part_name": "SEAT ASSY-FR,LH",
    "pel_codes": ["5693A3", "8811F2", "8821A5", "8836A1"],
    "source_row": 13
  }
}
```

현재 `alc2_convert.read_alc_full()`은 행 전체에서 영숫자 6자리 값을 수집하고 PEL 마스터에 존재하는 코드만 사용한다. 이 방식은 시작점으로 적절하지만, 미등록 코드 경고가 반드시 사용자에게 보여야 한다.

## 4. PEL CODE 마스터의 역할

PEL CODE 마스터는 아래 연결을 관리한다.

```text
PEL CODE → 사양 → 설명(동의어) → 옵션그룹 → 표시순서
```

예시 개념:

```text
5693A3 → T & P → THORAX, PELVIS → SAB → 120
```

사용 원칙:

1. PEL 코드가 있으면 `사양`을 기본 출력 사양명으로 사용한다.
2. `사양`이 비어 있으면 `설명`의 쉼표 구분 용어를 보조 이름으로 사용할 수 있다.
3. ★통합 ALC2 템플릿 열과 연결할 때는 공백·기호·대소문자를 정규화한 **완전일치**를 우선한다.
4. 같은 사양명이 여러 좌석이나 그룹에 반복되므로 좌석 상단 그룹까지 함께 비교한다.
5. PEL 마스터에 없는 6자리 코드는 무시하고 끝내지 말고 `미등록 PEL 코드`로 표시한다.

PEL CODE 마스터는 단순 목록이 아니라 O/X 변환의 기준정보다. 잘못된 `사양` 또는 `설명`은 O가 잘못된 열에 들어가게 한다.

## 5. O와 X의 정확한 의미

- `O`: 해당 생산 조합의 해당 좌석 ALC 원본 행에, 그 사양을 의미하는 PEL 코드가 존재한다.
- `X`: 해당 출력 열이 이 생산 조합에는 적용되지 않는다.
- 빈칸: X와 같은 의미로 임의 사용하면 안 된다. 템플릿상 O/X 대상 열이라면 미적용은 명시적으로 `X`를 써야 한다.
- 고정값: 일부 열은 `삼송`, `1`, `2`, 지역명, 부품번호 등 O/X가 아닌 값을 요구할 수 있다.

따라서 단순 로직은 다음과 같다.

```python
for output_column in template_option_columns:
    if output_column in matched_pel_columns:
        value = "O"
    else:
        value = "X"
```

단, 모든 열을 무조건 O/X로 덮으면 안 된다. NO, 차종, ALC-2 CODE, KMC ALC-2 CODE, 부품번호, 원단코드, 공급사, 고정 숫자 등은 열별 타입과 규칙을 따라야 한다.

## 6. 결과물 두 종류를 혼동하지 말 것

현재 웹은 결과물을 두 종류로 만든다.

### 6.1 `O·X 통합코드집` 동적 리포트

- PEL 마스터의 `사양/옵션그룹/표시순서`로 열을 동적으로 만든다.
- 발견된 사양에는 O를 표시한다.
- 비교·분석용 리포트로 유용하다.
- 그러나 ★통합 ALC2 원본 서식의 고정 278/283열과 동일한 결과물은 아니다.

### 6.2 `★통합 ALC2 코드 REV` 고정 서식

- 업로드한 최종 산출물 서식의 헤더, 병합, 색상, 열 순서를 그대로 보존한다.
- 각 생산 조합을 한 행으로 기록한다.
- PEL 사양을 고정된 좌석·옵션 열에 연결한다.
- 업무 최종 산출물은 이 파일이며, O뿐 아니라 미적용 X도 정확히 들어가야 한다.

동적 리포트가 맞다고 해서 고정 서식도 맞다는 뜻은 아니다. 두 결과를 별도로 검증해야 한다.

## 7. 2026-07-19 `origin/master` 구현 상태

확인 기준 커밋: `dc0bac0`

현재 구현된 내용:

- 6개 파일을 게시글에서 불러온다.
- Q파트의 `X`를 `****`로 처리하고 가변 KEY 그룹을 지원한다.
- ALC 행에서 6자리 PEL 코드를 수집한다.
- PEL CODE 마스터의 사양/설명으로 옵션명을 해석한다.
- 동적 `O·X 통합코드집`을 생성한다.
- ★통합 ALC2 원본 서식을 유지하면서 데이터 행을 교체한다.
- 후석 3개 슬롯을 고정 서식의 좌석 그룹에 매핑한다.
- PEL 마스터 미등록 코드를 경고한다.

아직 주의하거나 보완해야 하는 부분:

1. `SLOT_TOP_MAP`에는 후석 3개만 있고 FRT LH/RH는 제외돼 있다.
2. 전석은 LHD/RHD 판정 후 DRIVER/PASSENGER로 동적 연결해야 한다.
3. `_alc2_write_ledger()`는 현재 매칭된 열에 O만 쓰고 미적용 옵션 열에 X를 명시하지 않는다.
4. 동적 O/X 리포트도 미적용 값을 빈칸으로 쓰므로, 사용자가 요구하는 `O, X 표기`와 다를 수 있다.
5. 옵션 열 외의 부품번호·원단·KMC 좌석코드·지역·DRV TYPE 등 전체 278/283열 값 채우기는 별도 검증이 필요하다.
6. PEL `사양/설명`과 템플릿 leaf label의 완전일치가 안 되면 O가 누락된다.
7. `LUMBAR SUPPORT`, `THORAX`처럼 같은 좌석 안에서도 중복되는 라벨은 상위 옵션그룹까지 있어야 모호성이 해소된다.

이 문서의 목적은 위 미완성 지점을 바로 수정하라는 지시가 아니라, 현재 출력이 왜 일부 O만 표시되고 X 또는 전석 옵션이 빠질 수 있는지를 설명하는 것이다.

## 8. 권장 고정 서식 계산 구조

각 템플릿 열을 다음 메타데이터로 관리한다.

```json
{
  "column": "AF",
  "top": "DRIVER",
  "group": "POWER 옵션",
  "label": "LUMBAR SUPPORT",
  "value_type": "ox",
  "matched_pel_terms": ["LUMBAR SUPPORT"]
}
```

행 계산 순서:

1. Q파트 행에서 KEY별 좌석 ALC CODE를 얻는다.
2. 좌석별 ALC 원본 행에서 PEL 코드 집합을 얻는다.
3. PEL 마스터를 통해 좌석별 사양 용어 집합을 만든다.
4. LHD/RHD를 판정해 FRT LH/RH를 DRIVER/PASSENGER에 배정한다.
5. 템플릿 열마다 상단 좌석 + 그룹 + leaf label을 기준으로 사양을 매칭한다.
6. `value_type=ox`인 열은 매칭되면 O, 아니면 X를 쓴다.
7. 고정값/복사값/복합 조건 열은 각 타입별 규칙을 적용한다.
8. 각 셀의 계산 근거를 로그 또는 JSON으로 남긴다.

권장 추적 데이터:

```json
{
  "kmc_alc2": "507S607S604S****704S",
  "output_column": "AF",
  "output_path": "DRIVER > POWER 옵션 > LUMBAR SUPPORT",
  "result": "O",
  "source_slot": "FRT LH",
  "source_alc_code": "507S",
  "pel_code": "8821A5",
  "pel_term": "LUMBAR SUPPORT"
}
```

이 근거가 있으면 웹 화면에서 O/X 셀을 클릭했을 때 왜 O 또는 X인지 설명할 수 있다.

## 9. 필수 검증 시나리오

1. LHD 조합: FRT LH가 DRIVER, FRT RH가 PASSENGER로 들어가는지 확인
2. RHD 조합: FRT RH가 DRIVER, FRT LH가 PASSENGER로 바뀌는지 확인
3. 후석 3개: LH/CUSH/RH가 각 고정 상단 그룹에만 표시되는지 확인
4. 미사용 좌석: `X → ****`이며 해당 좌석 O가 생기지 않는지 확인
5. PEL 등록 코드: 해당 사양 열은 O, 같은 좌석의 미적용 O/X 열은 X인지 확인
6. PEL 미등록 코드: 결과 화면에 코드와 좌석 슬롯이 경고로 표시되는지 확인
7. 중복 라벨: 좌석과 옵션그룹이 다른 동일 leaf label을 잘못 찍지 않는지 확인
8. 기존 승인 조합: 웹 생성 결과와 기존 ★통합 ALC2 마스터 278/283열을 전 열 비교
9. 신규 조합: 기존 유사 행을 복사하지 않고 실제 PEL 기준으로 O/X를 계산하는지 확인
10. 출력 서식: 병합, 필터, 조건부서식, 메모, 헤더, 열 순서가 보존되는지 확인

완료 기준 예:

```text
비교 대상: 기존 승인 조합 20개
비교 열: 조합당 278개
전체 비교 셀: 5,560개
일치: 5,560개
불일치: 0개
미등록 PEL: 0개
```
