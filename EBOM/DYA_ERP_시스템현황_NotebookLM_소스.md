> **문서 성격**: 이 문서는 NotebookLM 등 문서 기반 AI 도구에 올려서 «전체 프로세스 개요»
> 다이어그램·설명서를 만들 때 쓰는 **원본 자료**입니다. 실제 운영 중인 코드와 데이터베이스에서
> 뽑아낸 내용이며, 추측이 아닙니다.

> **기준일**: 2026-08-03 · **운영 주소**: dyaerp.cloud · **게시판 링크 36개 / API 277개 / DB 테이블 61개**

## 1. 이 시스템이 하는 일

자동차 시트를 개발·생산하는 회사의 **기준정보(Master Data)를 한 곳에서 관리**하고,
그 기준정보가 설계 → 생산 → 구매 → 영업으로 **끊기지 않고 이어지게** 하는 시스템이다.

핵심 원칙은 하나다. **품번은 한 곳에서만 관리한다.**
품목 마스터(현재 441품번)에 등록된 품번·품명·차종을 BOM·도면·설계변경·재고가 **모두 같이 본다**.
품번이 갈라지면 «숫자는 맞는데 물건이 안 맞는» 상황이 생기고, 그 순간 아무도 시스템을 믿지 않는다.

## 2. 전체 흐름 (4단계)

```
① 기준정보 표준화  →  ② E-BOM 자동생성·검증  →  ③ M-BOM·ALC-2 변환  →  ④ 생산·영업 활용
   차종/국가코드         HKMC PEL → DYA E-BOM       Q파트 종합 + ALC 5종      생산 대시보드
   PEL CODE/원단코드     트리 전개·규칙 검증        매칭·신규 채번            계획/실적
   파트네임/개발단계     리비전 관리                DT 검증·O/X 변환          CCC 컬러코드
                                                   E-BOM ↔ M-BOM 비교        영업 단가
   [공통 참조 기준]      [검증된 설계 BOM]          [검증된 생산 BOM]         [실시간 의사결정]
```

이 네 갈래 위에 **가로로 걸쳐 있는 축**이 세 개 더 있다.

```
        ┌─ 도면 관리 (품목 · 카티아 2D/3D) ──────────────┐
        │                                                │
① ─ ② ─ ┼─ EO 시스템 (설계변경 통보서 · 고객 EO) ────────┼─ ③ ─ ④
        │                                                │
        └─ SCM (바코드 수불 · 재고 · 발주) ──────────────┘
                        ↑
                   협력사 도면 배포
```

## 4. 최근 추가·개선된 것 (이번 업데이트에서 반드시 반영할 내용)

### ① SCM 수불 관리 — 완전 신설
- **왜 만들었나**: 수불이 없으면 재경·회계가 원재료 재고와 원가를 잡을 수 없다.
- **왜 오픈소스를 안 붙였나**: ERPNext는 최소 4GB·권장 8GB RAM이 필요해 현재 서버(956MB)에서 못 돈다.
  GreaterWMS(포드 아태 A/S 물류 출신)는 별도 스택·별도 DB다. 자동차 시트 전용 오픈소스는 없다.
  결정적으로 **외부 WMS를 붙이면 품목 마스터가 갈라진다** — 수불이 현장에서 무너지는 가장 흔한 이유.
- **바코드**: USB 스캐너는 **키보드로 인식**(HID)되어 설치할 드라이버·프로그램이 없다.
  자동차 물류 라벨 **AIAG B-10 · VDA 4902**의 데이터 식별자(P 고객품번, 1P 공급사품번,
  Q 수량, 1T/H 로트, S 시리얼, V 공급사)를 읽어 **수량·로트까지 자동**으로 채운다.
- **설계 원칙**: 재고 테이블을 따로 두지 않는다. **재고 = 수불 원장의 합계**.
  둘이 어긋나는 순간 그 숫자는 아무도 믿지 않기 때문이다.
- **연결**: PLM은 같은 품목 마스터를 쓰므로 **이미 이어져 있다**. ERP는 원장이 원가의 바탕이 된다.
  **MES는 이미 구축돼 잘 돌아가고 있다.** 비어 있던 것은 그 앞뒤였다 —
  앞의 «기준정보»와 뒤의 «수불». SCM 원장이 MES 와 맞물리는 지점은 두 곳이다:
  MES 로 내려보내는 «검증된 생산 BOM·품번», MES 에서 받는 «라인 투입(출고)·완성품 실적(입고)».

### ② 카티아 자동 변환 — 실 CATIA R34로 검증 완료
- 사내 PC의 CATIA를 COM으로 불러 **CATPart → STP**, **CATDrawing → PDF** 자동 변환.
- 운영 서버 **83건 전량 변환 완료**. 더블클릭 실행 파일(`catia_convert.bat`) 제공.
- 변환 칸은 **색으로 형식을 구분** — 파랑 `STP ✓`(3D 형상), 주황 `PDF ✓`(2D 도면), 흐린 점선 `✗`(없음).

### ③ E-BOM 시트 리비전 — 시점 복원·되돌리기
- 목록에서 리비전을 **펼쳐 보고**, 시점별로 **열기·엑셀 받기·되돌리기**.
- **지나간 리비전은 읽기 전용** (서버가 저장 요청을 409로 거부).
- 되돌리기는 과거를 지우지 않고 **새 리비전으로 쌓는다**. 잘못 저장한 것은 «이 리비전 취소»로 지운다.

### ④ 협력사 도면 배포
- 협력사 계정(`role=partner`)은 **배포 게시판만** 볼 수 있다. 서버 미들웨어가 막는다.
- 「배포완료」 상태인 도면만 배포 가능. 받아 간 기록이 남는다.

### ⑤ 웹 3D 뷰어
- Online3DViewer + occt-import-js(OpenCASCADE WASM) **자체 호스팅**. STEP·PDF를 브라우저에서 연다.

### ⑥ 서버 성능
- 목록 응답 **742KB → 0.4KB**, 엑셀 재다운로드 **65초 → 0.12초**(리비전별 캐시).

## 5. 기술 구성

| 항목 | 내용 |
|---|---|
| 서버 | Oracle Cloud (dyaerp.cloud), Ubuntu, RAM 956MB |
| 백엔드 | Python FastAPI + Jinja2 |
| DB | SQLite (테이블 61개) |
| 웹서버 | nginx (업로드 2GB 허용) |
| 3D 뷰어 | Online3DViewer + occt-import-js (자체 호스팅) |
| CATIA 연동 | 사내 PC에서 COM 자동화 (서버는 리눅스라 CATIA를 못 돌림) |
| 바코드 | USB HID 스캐너 (드라이버 불필요) |

- **서버 증설** — 다차종 확대 시 ARM A1.Flex(최대 24GB 무료)로 이전 검토
